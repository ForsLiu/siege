Two play modes from the Title screen, both dev-tool aware. Mechanism only; every number that needs choosing goes into data/dev and QUESTIONS.md as provisional.

## A. Main mode = the roguelike run, plus a dev panel (dev builds only, toggle with F2)
Buttons, each backed by a sim Command in a `dev:` namespace so replays stay deterministic (the command log records them; production builds reject every `dev:` command):
- gold +10 / +50 / +1000
- xp +10 / +50 / +1000
- invincible pieces on/off (player units cannot drop below 1 hp during combat)  [designer note: "make pieces invincible" read as the player's units; a second toggle "invincible player" keeps player hp from dropping]
- skip round (resolve the current round as a win with normal rewards)
- add augment (pick any augment from data; opens the same chooser the game will use)
- open shop (free reroll into a chosen tier)
- spawn unit (any unit id, any star, to bench or a board hex)
- give item (any item id to the item bench)
The panel shows the seed and the content hash so a bug report can quote them.

## B. Battle sandbox (Title → Sandbox)
- Empty board; drag any unit from a full roster list to either side, set star level and items per unit, edit per-unit stat overrides (any stat in STAT_KIND) and the fight rules (max seconds, overtime on/off).
- Run once = visualised fight through the normal renderer at 1/2/4×, with a "replay this fight" button (same seed).
- Run N times = headless (N from an input, default 50), results table: win rate per side, mean and p95 fight length, per-unit damage dealt / taken / healed, deaths.
- Save / load a sandbox setup to data/dev/boards/<name>.json through the dev data endpoint, so saved setups become fight fixtures for tests and sweeps.
- Sandbox state is not a run: it never touches run state, save files or telemetry.

## Acceptance
- Test: every `dev:` command is rejected with a reason in a production build and accepted in a dev build.
- Test: replaying a run whose log contains dev commands reproduces every round hash.
- Test: sandbox N-run aggregation over a fixture matches a direct loop of fight() calls (same seeds, same results).
- Test: sandbox save → load round trip is identical.
- Manual checklist in PROGRESS.md for each button.
